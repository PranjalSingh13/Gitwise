GITWISE

Major Project Presentation Defense & Showcase Guide
Executive Pitch: "GitWise is an intelligent, multi-surface development companion designed to help engineers understand codebases, prepare pull requests, prevent security vulnerabilities, and diagnose Git errors using grounded AI and deterministic static analysis."

1. Why I Built GitWise (The Core Problem)

Software development today moves faster than ever, but developers—especially students, junior engineers, and open-source contributors—face three critical friction points:

  1. The "Foreign Codebase" Problem: When joining a new team or contributing to an open-source project, developers spend hours just trying to understand the architecture, key entry points, and dependencies. Existing documentation is often stale or missing.
  2. The "Silent PR Poison" Problem: Developers inadvertently commit hardcoded secrets (API keys, AWS tokens), unsafe SQL interpolations, or breaking database changes in Pull Requests. Generic AI tools often hallucinate or fail to catch deterministic regex security patterns.
  3. The "Cryptic Git Error Panic" Problem: Git is powerful, but its error messages (e.g., non-fast-forward rejection, merge conflicts, detached HEAD) are notoriously hostile. Frustrated developers often run dangerous commands like git reset --hard or git push --force, causing catastrophic loss of shared team history.

The GitWise Philosophy: Instead of building another ungrounded chatbot that invents answers, GitWise follows a strict engineering principle: Detect → Explain → Suggest → Verify → Learn. Deterministic tools verify facts first; Google Gemini 2.5 Flash explains and contextualizes second.

3. In-Depth Analysis: Pros & Advantages vs. Honest Limitations

✅ Core Strengths & Advantages (Pros)

  • Grounded AI (Zero Hallucination Security): Unlike pure LLM reviewers that invent line numbers or vulnerabilities, GitWise uses deterministic regex & OSV database queries first. AI only explains confirmed findings.
  • 100% Free & Scalable AI Infrastructure: Powered by Google Gemini 2.5 Flash (1M token context window, 1,500 free requests/day) with instant fallback to Groq (Qwen 3.8 / Llama 3). Zero cost for students and evaluators.
  • Universal GitHub URL Support: Users can analyze any public or private repository simply by pasting its URL (e.g., expressjs/express or owner/repo).
  • Defensible Health Score: Calculates transparent scores across 4 dimensions: Codebase Security (35%), Code Quality (30%), Dependencies (20%), and Documentation (15%). Outdated dev packages do not falsely trigger failing grades.
  • Safe Academy Simulator: A complete virtual Git state machine supporting git init, status, add, commit, log, branch, and revert without running arbitrary code on the server.

⚠️ Honest Limitations & Mitigations (Cons)

  • Static-Only Analysis (No Dynamic Sandbox): Limitation: GitWise does not execute repository test suites or build artifacts.
    Rationale: Running arbitrary untrusted user code on the backend creates extreme RCE security risks. Static inspection is safer for a cloud-hosted platform.
  • GitHub API Anonymous Rate Limits: Limitation: Unauthenticated GitHub API calls are limited to 60 req/hour.
    Mitigation: GitWise batches tree requests, uses raw content CDNs, and caches scan results by commit SHA.
  • Large Monolithic Repositories: Limitation: Repositories with over 10,000 files cannot be transmitted over HTTP in a single payload.
    Mitigation: Priority sorting filters top manifests (package.json, Dockerfile, entry points) to stay within token budgets.

5. Examiner Presentation & Live Demo Walkthrough (12-Minute Script)

Use this structured script when presenting to project supervisors, external examiners, or interviewers:

[Minutes 0:00 – 2:30] — The Hook & The Problem
  • "Good morning, examiners. Today I am presenting GitWise, an intelligent developer companion built to solve two critical problems: understanding foreign codebases and shipping safer code."
  • Explain the tension between fast development and accidental secret leaks in Pull Requests.
  • Introduce the core philosophy: Detect → Explain → Suggest → Verify → Learn.
[Minutes 2:30 – 5:30] — Live 1-Click Repository Deep-Scan
  • Open the Web Dashboard at http://localhost:5173.
  • Paste https://github.com/expressjs/express or your own repo URL into the Deep-Scan bar.
  • Click "⚡ SCAN REPOSITORY".
  • Show the live breakdown:
    • Health Score Card: Explain how 97/100 Grade A+ is computed across 4 dimensions.
    • Architecture Synthesis: Show how Gemini 2.5 Flash identified the framework and tech stack.
    • Strategic Action Plan: Highlight Priority 1, 2, 3 tasks generated for the developer.
[Minutes 5:30 – 8:00] — Pre-Merge PR Poison Scanner & Copilot
  • Switch to the "🛡️ PR Scanner" tab.
  • Click "📝 Load Risky Sample Diff" (contains an AWS key and raw SQL query).
  • Click "⚡ SCAN PULL REQUEST".
  • Showcase:
    • Critical Risk flag and redacted AWS credential.
    • Auto-generated conventional commit PR title and testing checklist.
    • Targeted reviewer checklist reminding the reviewer to check for SQL injection.
[Minutes 8:00 – 10:00] — Git Doctor & Academy Terminal Simulator
  • Switch to "🩺 Git Doctor". Show instant diagnosis for a rejected non-fast-forward push.
  • Switch to "🎓 Academy". Open Lesson 1.
  • Demonstrate typing standard Git commands in the terminal simulator: git init, git status, git add ., git commit -m "...".
  • Explain that this is a safe virtual state machine that prevents server-side security vulnerabilities.
[Minutes 10:00 – 12:00] — Multi-Surface Extensions & Conclusion
  • Briefly present the VS Code Extension (highlighting problems in the IDE) and the Chrome Extension (in-page GitHub button).
  • Conclude with the project's honest limitations (static analysis vs dynamic sandbox) and discuss future work.
  • Invite questions from the panel.
